name: character-narrative-skills-pets
description: Standards for character backstory writing, skill/ability design, and companion/pet pairing systems that drive both narrative investment and monetization. Use for any new playable character, skill tree, or pet/companion system.
---

CALIBRATION REFERENCES:
- Brawlhalla / Genshin Impact character design: each character has ONE clear mechanical identity readable in under 5 seconds of gameplay (e.g. "the slow heavy hitter," "the mobile glass cannon") — never design a character whose identity requires reading a wiki to understand.
- Fire Emblem / Pokémon pairing systems: companion bonuses tied to gameplay-meaningful synergy (not just flat stat stacking) create replay incentive to try different pairings.
- Hollow Knight/Hades: short, environment-and-item-told backstory (not exposition dumps) — lore delivered through item descriptions, brief dialogue, and world details rather than cutscenes, which suits mobile's low tolerance for reading long text.

CHARACTER DESIGN PROCESS (apply to every new hero):
1. Define the ONE mechanical hook first (speed, range, defense trade-off, unique verb like "can double-jump" or "attacks pierce"), before writing any backstory. Mechanics-first, lore-second — a character with rich lore but no clear mechanical identity fails in actual play; the reverse (clear mechanics, thin lore) still functions.
2. Backstory should be deliverable in under 100 words for a base-roster character, communicated through: a short bio line in the character-select screen, 1-2 lines of dialogue in relevant story beats, and visual design choices (never require a cutscene to establish identity for a non-premium character).
3. Explicitly state what this character is bad at, not just what they're good at — characters with no weakness read as "the best choice always," which kills roster diversity and, if the roster is monetized, actively hurts monetization because "the best one" becomes the only one worth acquiring/paying for.

SKILL TREE / PROGRESSION DESIGN:
- Skill trees should offer BUILD-DEFINING choices at key nodes (mutually exclusive options that change playstyle), not just linear stat-stick upgrades ("+5% damage" nodes in a row are the single most common "boring progression" complaint in mobile game reviews).
- Aim for a ratio of roughly 60% build-defining choice nodes to 40% flat-stat filler nodes in any skill tree — pure filler trees feel like busywork, pure choice trees can feel overwhelming for a mobile-casual audience.
- Every unlockable skill should be demonstrable in a single short animation/effect the player can immediately understand — if a skill's effect isn't visually obvious within 1-2 seconds of use, it needs stronger visual feedback, not a text tooltip as the primary explanation.

PET/COMPANION PAIRING SYSTEMS:
- Pet bonuses should create MEANINGFUL playstyle synergy with specific characters or builds (e.g. a pet that reduces cooldowns pairs meaningfully with a skill-spam character, not with a melee-only character) — synergy-based pairing gives players a reason to own/try multiple pets, which is a direct monetization lever (see monetization-shop-design skill) without feeling like pay-to-win if base performance stays fair.
- Avoid pure flat-stat pets with no character-specific synergy — they create a single "best pet" that trivializes the pairing decision and reduces perceived shop value of every other pet.
- Pet acquisition/pairing should be explained via a simple compatibility indicator in the UI (e.g. a highlighted synergy icon when a compatible character is selected), not require the player to consult external documentation to discover good pairings.

NARRATIVE DELIVERY FOR MOBILE (across all characters/pets):
- Never gate core gameplay understanding behind reading — narrative is a bonus layer, not a requirement, for a mobile action game audience.
- Keep individual dialogue/lore text blocks under ~40 words per screen; long blocks get skipped by mobile players almost universally.

WHEN DESIGNING A NEW CHARACTER OR PET:
1. State the one-sentence mechanical hook before anything else.
2. State the explicit weakness/trade-off.
3. State which existing characters/builds this pet or skill creates meaningful synergy with, and which it deliberately does NOT (a pet good with everything is a design smell).
