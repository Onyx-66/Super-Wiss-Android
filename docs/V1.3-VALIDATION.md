# Super Wiss Ascension v1.3.0 — validation status

This is a QA candidate, **not an accepted finished v1.3.0 release**. Full early-, middle- and late-world Android clears are still outstanding. The traversal driver in `tests/route-pilot.mjs` is experimental test tooling and is not shipped in the game bundle; its stalled attempts are not counted as completed runs.

## Implemented

- Responsive Heroes cards with role, mastery level, equipped state and a separate detail panel; Shop previous/next/swipe hero carousel.
- Full-width Records dashboard with mode, world, difficulty, hero and category filters, selected-run details and an intentional empty state. Rules revision 3 separates changed gameplay from v1.2 results while retaining old records in storage.
- Profile overview, achievements, heroes, cosmetics, records and social tabs; banner/frame editor and existing account actions retained.
- Icon-only active skill buttons; compact resource HUD; crouch input on touch, C/left Ctrl and gamepad stick click/D-pad down, preserved in all four migrated layout presets.
- Central cell occupancy validation and guarded runtime pickup creation. Lower static power-up budgets and reduced chest/block rewards. Coin guidance along room ledges.
- Saved `discoveredPowerUps` with a paused first-discovery card and Settings reset.
- Hero movement/attack timing profiles, original procedural weapon motion, bow arrows, staff casting, gadget shots, enemy anticipation/recovery/recoil and short melee impact pauses. Existing normalized PvP stats remain separate.
- Required underground seal descent, return climbing, a seal-powered lift and restored return bridge; vertically tracking camera, world-specific regional names/backgrounds, roster variants and timed environmental lanes.
- Streamed APK asset boot, safe mode, existing modes, temporary summons, control presets and save/account architecture retained.

## Automated evidence

- 203 Node tests pass, including all prior suites plus occupancy, crouch clearance, projectile timing, discovery migration, lift prerequisites and route tests.
- All 15 maps pass the conservative static jump-graph validator, including required seal access, cave return, stargate access and checkpoint hazard separation. It models terrain and conservative movement; it is **not** a complete playthrough or proof against every timed hazard/enemy combination.
- Responsive UI checked at 640×360, 800×360, 1280×720 and 960×440. Browser screenshots are `artifacts/v130-heroes-*.png`, `v130-records-*.png`, `v130-profile-*.png`.
- Browser tests cover real crouch input, icon-only skills, tutorial pause, persistence, repeat discovery, startup failures, Retry and Safe Mode. Tutorial tests explicitly inject two healing pickups solely to exercise the UI; they do not count as world clears.
- QA APK/AAB and debug builds, with QA/debug lint, completed successfully. Logs: `artifacts/v130-gradle.log`.

## Android runtime evidence

The current debug APK passed 16 Android smoke checks: staged boot to Home, all images decoded, world start, analog movement, jump, attack, dodge, knife, both skills, temporary summon, all four presets, an ordinary-input boss victory (Garsi, Veteran, 23.13 seconds, 3 hits), no uncaught JavaScript errors, WebView save reload, six-digit room creation and wrong-code rejection in the session layer. A separate full app process restart preserved the hero, four presets and boss record.

The signed QA APK was separately installed and cold-launched. Native logs reached `Home screen`. The admission test uses simulated session messages, not a Bluetooth radio pair. Screenshots are real runtime captures; the first boss screenshot includes Android's first-run fullscreen tip over the result panel and is retained as unedited evidence.

## Remaining acceptance work / limitations

- Complete representative early, middle and late worlds on Android through ordinary play. No such three-world completion claim is made.
- Complete visual/feel review of every hero state and all 15 worlds on physical hardware. Weapon overlays and existing animated sheets are not newly hand-drawn per-class animation libraries.
- Regions now require descent and return movement, but still use shared procedural structures and retain long connecting routes. This is not 75 individually authored regions.
- Environmental variants include shared timed hazard behavior. Broader enemy-specific art/attack variety and balance tuning remain necessary for the requested degree of world individuality.
- Full physical Bluetooth/radio, account server and device-performance certification remain unverified; inherited systems were preserved and regression-tested in simulation.
- Physical mobile swipe feel, all controller models, sustained 60 FPS and battery use require device testing.

## Reproduce

Run `npm test`, `npm run validate:maps`, `npm run build`, `npm run test:ui`, `node tests/upgrade-gameplay.cjs`, and `npm run test:browser`. Browser harnesses use installed Chrome and can locate Playwright through `PLAYWRIGHT_PATH`.

For Android, configure JDK 17 and the Android SDK, run `./gradlew.bat :app:assembleDebug :app:assembleQa :app:bundleQa :app:lintDebug :app:lintQa`, then run `tests/android-smoke.cjs` with `ADB` and `PLAYWRIGHT_PATH` set. The debug probe is excluded from QA/release. The QA certificate is public test signing, not a production key.

The first Android attempt hit an Android 17 preview emulator system-service boot loop before APK installation. A separate workspace data image was used to recover testing, preserving the previous emulator data. Installation/startup failures from that period are not app launch results.
