# Missing assets and remaining integration work

**Proposed paths below do not exist yet unless explicitly marked existing. They are not falsely registered as ready.** Each hero is listed separately to make the art workload visible. Task 4 and Task 7 are intentionally partial: functioning combat/data/renderer contracts do not create a complete set of new authored body/clothing images.

## Production contract
Current body sheets use 128×160 cells, fourteen frames in one row: idle0, run1–8, jump9, fall10, attack11–12, dodge13; draw envelope is 54×68 logical units. Maintain identical frame origin/feet alignment and alpha edges between every layer. Clothing must be rendered around a clean, appropriately covered neutral base, not around the existing fully clothed sprite. Produce foreground hand/arm/hair masks so held weapons can pass behind the gripping fingers. Separate rear masks are conditional.

The current legacy sheet has only two attack poses. The new simulation has three independent phases, but final bespoke anticipation/impact/recovery clips require authored poses **and a phase-to-clip mapping extension**. A larger 16+ frame atlas is possible, but do not silently change the existing 14-frame contract without updating the renderer, sockets and tests. Wissem's existing body is truly weapon-free. v1.4.1 uses its genuine idle0, not the attack cutout11 as a false guard; attack11–12 remain interim attack art. The other nine use labelled generic proxies in COMBAT only. Roster/detail/wardrobe identity views now show real existing character art with an explicit reference-only notice instead of green proxy blocks.

## Slot rendering and remaining architecture
The implemented order is rear → clean base → shoes → bottom → top → hat → eyewear → weapon → front hands/hair. `wardrobeItemReady` checks ready status, matching hero, aligned dimensions/frame count and the clean base/front mask contract. Weapon skins separately require a single image, class, grip anchor, angle and height and a separate body. Ownership and slot independence are persisted.

**Primary intended monetization expansion:** five independently sold clothing/accessory slots plus weapon skin multiply the potential cosmetic inventory and combinable looks compared with whole-outfit swaps. They do not multiply power. The current catalog is intentionally empty: no paid/earned price is charged for artwork that does not exist. When art is supplied, ready-item preview cards, real catalog pricing and source/sink/session-budget testing must be completed. Existing whole-look ownership remains available under Legacy looks; old purchases are not converted into imaginary individual clothing entitlements.

Per hero, plan at least five animated clothing layers and five preview images per first variant set, plus clean base/front mask and a class-matched weapon-skin image. Additional rear/occlusion splits and different unarmed animation layouts can increase that count; this is not a six-file quick patch.

Dedicated art remains required for approval. Baked-body unarmed combat still uses its marked training proxy (also lowered when crouching); only IDENTITY previews use actual hero reference art.

Each weapon skin needs compatible crouch sockets. The catalog is empty, so this is an explicit future rig requirement, not an invisible ready cosmetic feature.
